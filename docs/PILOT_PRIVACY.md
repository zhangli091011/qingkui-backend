# 试点隐私与未成年人数据边界

本说明用于青葵受控试点的产品、运维和教师操作。它不代替学校、试点组织者根据实际参与人群和所在地要求准备的告知、授权或监护人同意材料。未完成这些外部手续前，不得招募未成年人，也不得开启学校/班级能力。

## 试点前置条件

- 仅面向已批准的 5-10 人设备组发布，不公开分发安装包。
- 试点负责人应明确参与范围、使用期限、退出联系人、数据处理者和事故联系人。
- 未成年人参加前，由负责人完成适用的学校和监护人告知、授权及退出安排；应用内登录不视为替代授权。
- `ORGANIZATIONS_ENABLED=false`、`CREDIT_CAMPAIGNS_ENABLED=false`、`CONTRIBUTIONS_ENABLED=false` 和 `CONTRIBUTION_REWARDS_ENABLED=false` 保持关闭，除非对应能力另行通过审核。启用学校能力时必须同时设置 `PILOT_AUTHORIZATION_ENFORCED=true` 并逐人登记准入确认。

## 数据最小化

试点可能处理：账户名和昵称、设备会话、问答内容、学习状态、收藏、笔记、反馈、错题图片及 OCR 结果、模型用量和额度流水。参与者不应提交真实姓名、身份证件、手机号、精确住址、精确位置或与学习无关的个人信息，账户名和昵称也不得包含这些内容。

Android 客户端不保存 OSS 或模型服务密钥。错题图片保存在私有 OSS，由已认证的后端接口执行上传、签名访问和删除。PostgreSQL 保留业务记录，向量索引和原始知识文档与用户个人数据分离。

## 模型处理边界

后端只向当前配置的问答、向量、重排或 OCR 服务发送完成本次学习任务所需的内容。不得在提示词、日志或评测文件中附加无关的账户标识。模型输出可能不准确，正式内容仍受发布范围、来源、公式复核和人工评测门控制。

## 访问控制

- 学生只访问自己的账户、会话、学习记录、错题和反馈。
- 系统管理员只因故障处理、内容审核、额度核对或数据清理访问必要信息，并由审计日志记录管理操作。
- 学校/班级能力默认关闭。启用后，教师概览只返回班级聚合和稳定匿名学生 ID，不返回用户名、昵称、题目、回答、笔记、反馈正文或图片。
- 学生邀请码在写入成员关系前校验有效准入，撤销准入会同步停用学校和班级成员关系；授权依据只记录文件编号或确认方式。
- 任何实名教师视图都必须另行记录授权范围、授权人、目的和有效期，不能沿用匿名概览授权。

## 删除、退出与备份

- 用户可以删除错题和会话；删除错题时同步删除对应 OSS 图片。
- 注销会删除在线账户、认证会话和个人学习数据，并将必须保留的审计事实匿名化。
- 试点结束或参与者退出后，管理员先使用清理预览确认精确用户 ID 和数量，再执行试点清理；禁止按模糊条件批量删除。
- 已删除数据可能暂时存在于加密或受限的灾备副本中，副本只用于灾难恢复，按运维保留周期自然过期，不得恢复到日常环境继续使用。

## 教师与试点负责人操作要求

1. 不要求学生在提问、昵称或图片中填写真实身份信息。
2. 不把匿名学生 ID 与校内实名表拼接，也不导出题目、回答、笔记或图片建立影子档案。
3. 发现身份证件、联系方式或其他无关个人信息时停止传播，记录最小必要事故信息并联系系统管理员清理。
4. AI 答案用于学习辅助，涉及评分、处分、分班或其他重要决定时必须由教师独立核验，不能自动决定。
5. 试点结束后导出匿名聚合指标，完成精确数据清理和恢复点核验，再决定是否扩大范围。

## 发布门

试点包发布记录必须包含批准 commit、APK SHA-256、签名与版本号、参与设备组、责任人、试点起止时间、退出联系人和本说明版本。任何一项缺失时保持内部验证状态，不进入未成年人试点。
