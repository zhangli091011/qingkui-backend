# 知识状态与有效证据

知识状态用于安排复习，不能把“看过”或客户端自报当作“已验证”。服务端是状态事实来源，Android 只展示服务端返回结果。

## 状态规则

- `unexplored`：尚无学习事件。
- `explored`：打开过节点。
- `understood`：学生主观标记已理解，不代表通过检查。
- `unstable`：学生标记还不懂，或理解检查未通过。
- `error_prone`：已确认的高风险/易错状态。
- `to_explore`：进入后续探索队列。
- `verified`：只由服务端确认的有效证据产生。

## 有效证据

当前有两类证据可进入 `verified`：

1. 服务端创建的一次性理解检查。选项使用不透明 ID，15 分钟内仅能提交一次；答案由服务端判定，通用学习事件不能自行声明 `passed=true`。
2. 错题练习由服务端规则校验器得出正确结果，且 `authoritative=true`，并已关联到明确知识节点。客户端自报正确、开放题或无法可靠判分的回答不能升级状态。

理解检查只为 `approved`、`is_active=true` 且定义非空的节点生成，干扰项同样来自同学科、同年级的已审核节点。正式数学节点未完成人工审核前不会获得检查入口。

## 事件审计

通过理解检查时记录 `completed_check`，只保存尝试 ID、是否通过和题型，不记录选择文本副本。通过权威错题练习时记录 `completed_mistake_practice`、练习 ID 和校验方法。失败的理解检查将节点设为 `unstable` 并进入待复习列表。
